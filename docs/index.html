Voting methods and ballot analysis

Model an electorate once, preserve its ballots, and see how plurality, ranked, approval, score, Condorcet, and multi-winner rules turn the same preferences into different collective choices.

Tool: votingInterface: JSON-first CLIMethods: 28 names and aliases

01 Why the voting method matters

A ballot records individual preference; a counting rule converts many ballots into a winner, ranking, or set of seats. That conversion is a modeling choice. Plurality sees first choices, Borda uses every rank, approval measures acceptable breadth, and Condorcet rules examine every head-to-head contest.

result = f(options, electorate, ballots, rule, tie policy)Change the rule while holding the other inputs fixed, and the collective outcome can change.

Single winner

Select one candidate, proposal, product concept, or priority.

Collective ranking

Order alternatives rather than reporting only the top choice.

Multiple seats

Choose a slate using proportional or bloc-style representation.

Method comparison

Test whether a conclusion survives reasonable alternative rules.

The core habit. Define what voters can express before choosing how to count it. A richer rule cannot recover preferences that the ballot never collected.
Scope boundary. This package supports research, education, scenario analysis, and decision modeling. It does not provide identity verification, secret-ballot infrastructure, cryptographic auditing, statutory compliance, or production election security.

02 The data model

A project is a local directory with a .voting/ state tree. Options and voters exist independently of elections. An election selects eligible options, a default method, a ballot format, seats, and a tie policy. Ballots connect voters to elections.

ObjectKey fieldsPurpose
OptionID, name, type, eligibilityA candidate, proposal, reference, or write-in.
VoterID, name, weight, traits, eligibilityA person, stakeholder group, or synthetic persona.
ElectionMethod, ballot type, seats, options, statusThe rules and eligible choice set.
BallotVoter, election, preferences, weightOne recorded expression of preference.
ResultMethod, winners, ranking, summary, diagnosticsAn immutable count snapshot.

Ballot records are append-only. If one voter casts again in the same election, the latest record is used for counting while the earlier record remains on disk. That makes corrections possible without erasing history.

project/
└── .voting/
    ├── meta.json
    ├── options/       # one JSON file per option
    ├── voters/        # one JSON file per voter
    ├── elections/     # one JSON file per election
    ├── ballots/       # append-only ballot records
    ├── results/       # saved count snapshots
    └── output/        # generated survey artifacts

05 Install and initialize

The worked example chooses one neighborhood project from three proposals. Install the package, create a project, and enter its directory.

git clone https://github.com/expectedparrot/voting.git
cd voting
pip install -e .

voting init neighborhood_vote
cd neighborhood_vote
voting status

Commands emit structured JSON by default. Put --human before the subcommand for readable terminal output, or set VOTING_HUMAN_OUTPUT=true.

voting --human status
voting docs list
voting docs show getting-started

06 Register options and voters

IDs are stable join keys: lowercase letters, numbers, and underscores, without a leading digit. Names are presentation labels and may contain spaces.

voting option add library "Extend library hours" --type proposal
voting option add shelters "Build covered bus shelters" --type proposal
voting option add lighting "Upgrade park lighting" --type proposal

voting voter add voter_1 "Avery"
voting voter add voter_2 "Blake"
voting voter add voter_3 "Casey"
voting voter add voter_4 "Devon"
voting voter add voter_5 "Emery"

voting option list
voting voter list

Weights default to 1.0. Use traits to record relevant metadata or a readable persona for EDSL survey generation. Do not use an opaque ID itself as evidence about a voter.

voting voter set-trait voter_1 persona \
  '"Daily bus rider who also uses the library on weekends"'

07 Create and open an election

An election begins in draft. Add its eligible options, inspect it, and only then open balloting.

voting election add neighborhood_ranked "Neighborhood project choice" \
  --method irv --ballot-type ranked

voting election add-option neighborhood_ranked library
voting election add-option neighborhood_ranked shelters
voting election add-option neighborhood_ranked lighting

voting election show neighborhood_ranked
voting election open neighborhood_ranked
Eligibility is election-specific. An option may remain in the project registry for historical continuity while being omitted from a particular election.

08 Record ranked ballots

Rank options from most to least preferred. Partial rankings are allowed; unlisted options are generally treated as tied last. Duplicate option IDs are rejected.

voting ballot rank neighborhood_ranked voter_1 library shelters lighting
voting ballot rank neighborhood_ranked voter_2 library lighting shelters
voting ballot rank neighborhood_ranked voter_3 shelters lighting library
voting ballot rank neighborhood_ranked voter_4 lighting shelters library
voting ballot rank neighborhood_ranked voter_5 shelters library lighting

voting ballot list --election neighborhood_ranked

Other ballot formats use commands shaped for their data:

voting ballot cast election_id voter_1 --choice library
voting ballot approve election_id voter_1 --option library --option shelters
voting ballot score election_id voter_1 library=8 shelters=9 lighting=4
voting ballot grade election_id voter_1 library=A shelters=B lighting=C
voting ballot allocate election_id voter_1 library=40 shelters=35 lighting=25

09 Validate before counting

Validation uses the latest ballot for every voter and checks registration, voter eligibility, option eligibility, duplicate ranks, and allocation budgets. Invalid ballots produce warnings and are skipped by the count.

voting ballot validate neighborhood_ranked
voting election close neighborhood_ranked
voting count run neighborhood_ranked
voting count list --election neighborhood_ranked
voting count show <result_id>

IRV repeatedly eliminates the last-place option and transfers its ballots to the next continuing preference until a majority remains.

10 Compare methods without rewriting ballots

Ranked ballots contain enough information for several alternative counts. Override the configured method at count time; each run is saved separately.

voting count run neighborhood_ranked --method fptp
voting count run neighborhood_ranked --method borda
voting count run neighborhood_ranked --method copeland
voting count run neighborhood_ranked --method ranked_pairs
voting count run neighborhood_ranked --method schulze

voting count list --election neighborhood_ranked
Interpret differences, do not hide them. A method comparison is a sensitivity analysis. Report which preference information each rule uses, whether winners change, where ties or cycles occur, and why the chosen rule fits the decision.

Condorcet methods build a pairwise matrix. For options a and b, the cell counts the weight of voters who rank a above b.

P(a,b) = Σ wi · 1[a ≻i b]A Condorcet winner has P(a,b) > P(b,a) against every other b.

11 Synthetic and human surveys

If registered voters represent synthetic personas, voting can generate a standalone EDSL survey script. Inspect the prompts, run the script in an environment with EDSL installed, then import its result JSON.

voting survey generate neighborhood_ranked

# Inspect before execution:
voting --human survey show neighborhood_ranked

# EDSL is an optional, separate dependency:
python .voting/output/survey_neighborhood_ranked.py

voting ballot import --election neighborhood_ranked \
  --from .voting/output/results_neighborhood_ranked.json
voting ballot validate neighborhood_ranked
Label the evidence. Preferences produced by language-model agents describe a simulated electorate. They are useful for scenarios and experiments, but they are not observed public opinion or a substitute for human respondents.

Publish a survey for human voters

Humanize uses the same election and options to build a model-free EDSL Jobs package, then creates a hosted survey through the ep CLI. Publishing returns a respondent URL you can share and an admin URL for monitoring responses. Choice order is randomized independently for each respondent by default; pass --no-randomize-options only when order is meaningful.

pip install -e '.[humanize]'

voting survey humanize neighborhood_ranked
voting survey publish neighborhood_ranked

# Download submitted responses as an EDSL Results package:
voting survey responses neighborhood_ranked

For individual email invitations, give each registered voter an email trait before generating the job. Humanize creates a respondent list with unique links; the delivery command asks Expected Parrot to email its standard invitation template.

voting voter set-trait voter_1 email '"avery@example.com"'
voting voter set-trait voter_2 email '"blake@example.com"'
# Repeat for every registered voter.

voting survey humanize neighborhood_ranked --email-trait email
voting survey publish neighborhood_ranked
voting survey email neighborhood_ranked \
  --name "Neighborhood vote invitation" \
  --subject "Please cast your neighborhood vote"
Two distinct paths. survey generate asks AI agents for synthetic preferences. survey humanize creates a web survey for real people and contains no language model.

12 Multi-winner elections

Set --seats when creating an election, or override it for a count. The rule determines what representation means.

MethodBallotRepresentation logic
stvRankedElects candidates who reach a Droop quota and transfers surplus and eliminated ballots.
sntvSingle choiceEach voter casts one vote; the top N options win.
block_votingApprovalTop N approval totals win; cohesive majorities can sweep seats.
limited_votingApprovalVoters approve fewer options than available seats.
cumulativeAllocatedVoters concentrate or spread a vote budget.
voting election add council "Advisory council" \
  --method stv --ballot-type ranked --seats 3

# Or explore a different seat count without changing the election record:
voting count run council --method stv --seats 4

13 Weights, incomplete ballots, and ties

A voter’s weight is copied onto newly recorded ballots. Weighting can represent stakeholder groups or survey weights, but it changes the effective electorate and must be documented. Equal weight is the safest default when no defensible scheme exists.

support(a) = Σi wi · supporti(a)One heavily weighted ballot can contribute as much as many ordinary ballots.
  • Partial ranking: unranked options carry no later transfer preference and can create exhausted weight.
  • Abstention: represent it explicitly in analysis notes; do not invent a preference.
  • Ties: the default policy is lexicographic, which is deterministic but substantively arbitrary.
  • Recounts: pass --tie-policy to record an alternative policy in the result snapshot.
voting count run neighborhood_ranked --tie-policy lexicographic

14 Preserve an auditable analysis

Every reported conclusion should be traceable to a project state and a saved result. Keep IDs stable, validate before each run, and retain the method name, seats, tie policy, warnings, valid weight, exhausted weight, ranking, and winner list.

CheckWhy it matters
Same electorateMethod comparisons are misleading if voter inclusion changes.
Same eligible optionsAdding or withdrawing an option can change transfers and pairwise contests.
Compatible ballot evidenceA rule should not be credited with information voters never supplied.
Warnings disclosedSkipped ballots and exhausted weight affect the meaning of a result.
Saved result IDsReaders can reconnect claims to exact count snapshots.
